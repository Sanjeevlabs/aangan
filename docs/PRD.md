# AANGAN V1 PRD

## Thesis
"Far apart, still together." Most family apps make parents feel cared for; Aangan makes them feel NEEDED.
Values, in priority order: Needed (elders give and have a role) · Heard (acknowledgement) · Present (together at the same time) · Remembered (memories) · Never watched (no monitoring, no guilt).
For families anywhere in the world. Calm by design: no stories, status, counts, comments or infinite feed.
Brand: "Aangan: the family courtyard". Display languages: English · Hinglish (Hindi in English letters) · हिंदी (Devanagari). The viewer's display_lang drives UI strings, captions, transcripts, synced lyrics, role prompts, and kinship names (Grandma / Dadi / दादी for the same person). Seed data provides strings for all three display languages. Onboarding step (right after the home photo): "How should Aangan speak to you?" with three options, each shown in its own script: English · Hinglish (Hindi in English letters) · हिंदी. Changeable anytime in the profile menu. members.display_lang: 'en' | 'hi-latn' | 'hi-deva'. Default if unset: 'en'.

## P0 scope (must ship)
1. Welcome screen: onboarding step 1 "Add a photo of the home you miss: a courtyard, a window, a doorway" (hint: avoid house numbers/street signs). Per-member home_image, family default, fallback illustrated courtyard. Full-bleed image + bottom glass card: greeting, "Welcome to <first name>'s Aangan" (serif), one warm signal line (e.g. "Dadi heard your voice note · 2 new blessings"), "Change home" (outlined) + "Step inside" (primary). Its colors seed the member's adaptive wash. Shown once per session.
2. Daily role (ikigai): the first Home shelf for elders, e.g. "Today: teach Aria one word" / "Bless Leo's exam". Generated by the ritual agent; the elder answers by voice -> becomes a card.
3. Two-way voice + Heard loop: plays(card, member, played_at); the sender sees a glass chip "Dadi heard this · 9:14". Pipeline: transcribe -> translate/transliterate per the viewer's display_lang via muse-spark-1.3 (structured output), cached per card + lang. Store the original transcript too.
4. Reactions: exactly three, Love, Laugh, Bless (Bless labelled on long-press). Shown as text ("Leo laughed at this", "Dadi blessed this"), never counts. One per member per card. Long-press -> reply by voice. reactions(card, member, kind, created_at).
5. Home (presence): shelves "Today's role" (elders) / "From Dadi" (children), "Voices", "Today · add from your day", "This day, years ago", "Coming up". "Record for them" always one tap away.
6. Now playing: big square art, artwork-tinted wash, live voice frequency waves (Web Audio AnalyserNode; stored peaks when static), scrubber, synced lyrics-style transcript (Voice Transcribe segment timestamps if returned, else per-sentence estimate). Glass control pill; glass mini-player app-wide.
7. Add sheet (glass): photos from today (multi-select, shared family pool), voice, video <=30s, ask an elder a question (muse-spark-1.3 suggests prompts).
8. Memory cards: grounded captions in the viewer's display_lang; video cards captioned and dated via Muse Spark video understanding.
9. Memory Lane: chips (All, Voices, Rituals, Bonds), season+year chapters, vertical spine, keepsakes of varied widths, glass caption panels on photos.
10. Rituals: calendar built from family-graph birthdays/anniversaries + data-driven ritual_configs (no festival names in logic). Movable festival dates are resolved per year via search grounding and cached; never hard-coded.
11. Ritual agent: 7 days before an occasion, request wishes from members AND blessings from elders, remind the missing at day 3, assemble the Birthday Reel, deliver at 8 am in the recipient's time zone. Also assigns daily roles.
12. Birthday Reel (two-way): segmented progress, each wish/blessing plays with synced lyrics, "Happy birthday, <viewer-relative name>", "Reply with voice", petal effect.
13. Family Bond: guided add ("Add Dadi as Dad's mother"), auto generational SVG tree (spouses, two parents), branch-grow animation, "Welcome to the family" bloom + Bond card. Kinship: deterministic BFS path -> kinship_cache(path, lang); model only on a cache miss.
14. Gather (a family evening): date + each member's local time (Intl), invites, playlist curated by muse-spark-1.3 from the Lane, "Start together".
15. Glasses badge: read EXIF Make/Model before stripping; Meta/Ray-Ban/Oakley -> source='glasses', badge "Captured hands-free"; manual "From my glasses" toggle as fallback.
16. Agent trace page, the privacy set, golden evals.

## Design system
Light-first, dark supported. Sans UI; serif titles, captions and lyrics. Tokens in one file.
Adaptive light wash: 2-3 large blurred glows drifting slowly, default warm peach; colors from the home image / artwork (client canvas). Still under reduced motion.
Glass ONLY on sheets, tab bar, mini-player, player controls, photo caption panels and agent suggestion cards: backdrop-filter blur(40px) saturate(1.4); rgba(255,250,245,0.72) (dark rgba(40,30,25,0.6)); 0.5px border rgba(255,255,255,0.6); radius 32px, pills 999px, round close button; shadow 0 20px 60px rgba(60,40,30,0.18); solid fallback.
Buttons: primary = dark espresso pill, secondary = outlined pill. Cards: Spotify-inspired square artwork, artwork-tinted, in horizontal shelves. Motion: framer-motion, 150-400ms.
Tab bar (glass): Home · Lane · Add (raised centre) · Rituals · Gather. Profile menu: Family Bond, Elder mode, Share a skill (coming soon).

## Agents
One runAgent(goal, tools, maxSteps=6) using muse-spark-1.3 tool calling. Tools: read_family_graph, query_lane, create_card, schedule_notification, create_gather_session, request_wish, assign_daily_role.
Agents write `suggestions`; actions execute only on approval via a glass "Aangan suggests · Review / Approve" card. Log to agent_runs + llm_calls; a minimal /trace page. Mock fixtures + a mock test per agent.

## Meta models
- muse-spark-1.3: captions, roles, kinship terms, prompts, playlists, agents, video understanding, search grounding. Structured output only. Prompt caching for long system prompts; log cache hits.
- Muse Voice Transcribe: voice, wishes, lyrics.
- Muse Image: seed script only (synthetic, diverse, global demo family photos + fallback courtyard), generated once into public/demo/ with an AI-generated notice. Never invent people or events in real cards.
- SAM 3.1: P1 stickers.
- Optional: Baseten meta-models/muse-spark-open-1026 as a failover provider, only if credits are confirmed. All model IDs in config.

## System design (lean; no extra infra)
Single Next.js app on Vercel; Supabase (Postgres+RLS by family_id, private Storage + signed URLs, Realtime, anonymous auth + invite codes expiring in 7 days). All model calls server-side via lib/llm.ts. Triggers: route handlers on events + one daily Vercel Cron for ritual/role scans. No queues, workers or push notifications.
Client media pipeline: compress -> read EXIF date + Make/Model -> strip all other EXIF (GPS) via re-encode -> dominant color -> waveform peaks -> direct upload via signed URL -> POST /api/cards -> status processing->ready via Realtime.
cards.source: upload|today|glasses|ritual|agent.
Tables: families, members(+home_image, lang, display_lang, tz), relationships, cards(+transcript, transcript_lang, segments), media, plays, reactions, daily_roles, ritual_configs, ritual_runs, wishes(kind: wish|blessing), gather_sessions, suggestions, agent_runs, llm_calls, kinship_cache(path, display_lang), invites. Supabase column display_lang mirrors Member.displayLang; legacy lang stays in sync (hi-deva -> hi, else en).

## Privacy
EXIF/GPS strip; private bucket + signed URLs; first-record voice consent, voices never cloned; no face recognition or auto-tagging of minors; "Remove my memories" + "Leave family" fully delete; expiring invites; in-app disclosure "Demo mode: AI providers may process content".
